# 📜 Code of Conduct

## Notre Engagement

Globe Radio Vibe s'engage à offrir un environnement accueillant et inclusif pour tous, indépendamment de :
- L'âge, la taille du corps, le handicap visible ou invisible
- L'origine ethnique, l'identité et l'expression de genre
- Le niveau d'expérience, l'éducation, le statut socio-économique
- La nationalité, l'apparence personnelle, la race, la religion
- L'identité et l'orientation sexuelle

Nous nous engageons à agir et interagir de manière à contribuer à une communauté **ouverte, accueillante, diverse, inclusive et saine**.

---

## Nos Standards

### ✅ Comportements Attendus

- 🤝 **Respect mutuel** : Traiter tous les membres avec respect et dignité
- 💬 **Communication bienveillante** : Utiliser un langage constructif et inclusif
- 👂 **Écoute active** : Accueillir les perspectives différentes
- 🔍 **Accountability** : Accepter les critiques constructives avec grâce
- 🙏 **Empathie** : Comprendre les expériences différentes
- 🚀 **Collaboration** : Travailler ensemble pour le bien du projet
- 📚 **Pédagogie** : Aider les nouveaux contributeurs à s'intégrer
- 🔐 **Confidentialité** : Respecter la vie privée d'autrui

### ❌ Comportements Inacceptables

Les comportements suivants sont **strictement interdits** :

- 🚫 **Harcèlement** : Commentaires offensants basés sur les caractéristiques protégées
- 🚫 **Intimidation** : Menaces, intimidation ou tentatives de contrôle
- 🚫 **Discrimination** : Traitement injuste basé sur des caractéristiques personnelles
- 🚫 **Abus sexuels** : Contenu sexuel non consentis, avances non désirées
- 🚫 **Spam** : Promotion excessive, auto-promotion non pertinente
- 🚫 **Sabotage** : Tentatives délibérées de nuire au projet
- 🚫 **Doxing** : Partage d'informations personnelles sans consentement
- 🚫 **Langage violent** : Menaces, insultes, langage abusif
- 🚫 **Mauvaise foi** : Arguments non constructifs ou trolling
- 🚫 **Violations légales** : Partage de contenu illégal ou non autorisé

---

## Nos Responsabilités

### Mainteneurs & Modérateurs

Les mainteneurs du projet sont responsables de :

1. **Clarifier** les standards de conduite acceptable
2. **Prendre des mesures correctives appropriées** face à tout comportement inacceptable
3. **Modérer les discussions** pour maintenir un environnement sain
4. **Appliquer les règles** de manière équitable et cohérente
5. **Protéger la confidentialité** des personnes signalant des violations
6. **Documenter les incidents** et les résolutions

---

## Application des Sanctions

### Niveaux d'escalade

#### 🟡 Niveau 1 : Avertissement Informel
**Situation** : Commentaire malencontreux, ton inadapté  
**Action** : Discussion privée, clarification des attentes

**Exemple** :
```
"Bonjour [Personne],

J'ai remarqué que votre commentaire pourrait être mal interprété. 
Pourrions-nous reformuler pour être plus constructif ?

Merci."
```

#### 🟠 Niveau 2 : Avertissement Officiel
**Situation** : Violation répétée du Code of Conduct, comportement discourtois  
**Action** : 
- Avertissement public sur la PR/Issue
- Suspicion temporaire des contributions (7 jours)
- Demande de formation/clarification

#### 🔴 Niveau 3 : Suspension Temporaire
**Situation** : Harcèlement, discrimination, comportement toxique  
**Action** :
- Suppression des commentaires offensants
- Suspension du repo access (1 mois)
- Communication avec GitHub si violation extrême

#### ⛔ Niveau 4 : Bannissement Permanent
**Situation** : Harcèlement grave, menaces, contenu illégal  
**Action** :
- Bannissement définitif du projet
- Signalement à GitHub Trust & Safety
- Signalement aux autorités si légalement requis

### Processus d'Appel

Si vous estimez qu'une sanction est injuste :

1. Envoyez un email à **[contact maintainers]** dans les 14 jours
2. Fournissez votre perspective sur la situation
3. Les mainteneurs examineront le cas et répondront sous 7 jours
4. Décision finale sera communiquée avec explications

## Signaler une Violation

### Comment Signaler

**Pour les violations **privées** (harcèlement personnel, menaces)** :

📧 Envoyez un email à : `[email à remplir]`

Incluez :
- Description détaillée de l'incident
- Captures d'écran/liens pertinents
- Date et heure de l'incident
- Toute documentation supplémentaire

**Pour les violations **publiques** (spam, discrimination)** :

1. Cliquez sur **"Report content"** sur GitHub
2. Ou créez une issue privée : **"[REPORT] Description"**
3. Les mainteneurs examineront dans les 48h

### Confidentialité & Protection

- ✅ Les rapports sont **traités confidentiellement**
- ✅ L'identité du rapporteur est **protégée** (sauf exception légale)
- ✅ Les signaleurs de bonne foi **ne seront jamais pénalisés**
- ✅ Les faux rapports **peuvent entraîner des sanctions**

## Exemples Pratiques

### ✅ Commentaires Constructifs (Acceptés)

```
"Je pense qu'il y a une meilleure approche pour cette implémentation. 
As-tu considéré d'utiliser [alternative] ? Voici pourquoi ça pourrait 
être plus performant : [explication]. Qu'en penses-tu ?"
```

```
"Je ne comprends pas cette logique. Pourrais-tu expliquer pourquoi 
tu as choisi cette approche plutôt que X ?"
```

```
"Le code fonctionne, mais j'ai quelques inquiétudes concernant 
la maintenabilité. Peut-être pourrions-nous refactoriser ensemble ?"
```

### ❌ Commentaires Inacceptables (Interdits)

```
"C'est du code débile. Tu ne sais clairement pas programmer."
```

```
"Les femmes ne devraient pas être dans la tech. Retourne à la cuisine."
```

```
"Ton PR est une ordure. Je vais spammer le repo jusqu'à ce que tu partes."
```

```
"J'ai trouvé ton adresse. Attention à toi..."
```

## Inclusion & Diversité

### Principes

- 🌍 **Accueil des perspectives diverses** : Les backgrounds différents enrichissent le projet
- 📚 **Accessibilité** : Documentations claires, accès facilité
- 🤲 **Support des novices** : Pas de question "bête"
- 🗣️ **Langues** : Communication en anglais/français bienvenue
- ♿ **Accessibilité numérique** : Effort pour inclusivité (alt text, captions)

### Langage Inclusif

- ✅ Utilisez des pronoms appropriés (demandez si incertains)
- ✅ Évitez le sexisme (ex: "développeurs" au lieu de "devs masculins")
- ✅ Pas d'idioms offensants ou stéréotypes
- ✅ Respectez les noms et prononciations

**Exemple de correction bienveillante** :
```
"BTW, je pense que tu faisais référence à 'les contributeurs' 
plutôt que 'les gars' pour inclure tout le monde 🙂"
```
